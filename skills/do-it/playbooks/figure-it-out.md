# Figure it out

No narrower playbook fits (migration, multi-part change, long unattended run). Design an auditable plan first; then execute.

1. Frame: falsifiable done predicate, quantified scope, rigor level (bias high for one-way doors). Present framing before a multi-hour run.
2. Design phases: riskiest-unknown first; each phase ends in a check. Prefer Call the Skill tool with `"verify-work"` at phase boundaries that touch runtime.
3. Write the phase list into the todolist. That list is what the human audits.
4. Execute phase by phase. Bugs inside a phase → Call the Skill tool with `"debug-root-cause"`. Repeating lessons → Call the Skill tool with `"living-docs"`.
5. End with overall proof against the done predicate.

**Reply:** framing, phase outcomes, final proof, open risks.
